# IDI 相机 0.5.10 · 官方原生版

安卓 APK 使用用户提供的 **XheyCameraSDK 1.3.70.9b61b4a6 Android** 拍摄，保留案件选择、内容编辑、本地照片和上传记录。支持 Android 8.0 及以上的 ARM 手机；包内包含 arm64-v8a 和 armeabi-v7a 官方库。

## 使用流程

1. 在运行 IDI 的电脑打开 `http://127.0.0.1:8766/camera-setup`，启用已保存的 SDK 授权，选择项目并生成配对码。
2. 安装 0.5.10 APK，由 IDI 系统管理员选择人员和所属项目生成配对码，输入服务器地址和配对码后「连接并同步」。已有版本可用同一发布签名覆盖升级，保留手机记录。IDI 0.2.37 起，历史设备需重新按人员配对。
3. 选择案件或点击「拍照」，允许相机和精确位置权限后直接进入官方预览，并自动弹出水印设置。手动填写或确认环节、部位和照片内容，保存后继续取景；取景时点击水印可再次修改。0.5.1 已移除水印面板的语音填写入口及识别调用。
4. 预览顶部选择「拍照」或「录像」。每张照片保存后直接恢复当前相机预览，沿用当前案件、环节、部位和内容；不关闭相机或闪回案件页，按返回键结束连拍。每张使用独立编号保存并排队上传。切换拍照／录像或修改水印时，保留当前相机画面并显示切换提示，待新预览就绪后恢复操作。录像首次使用需允许麦克风，每段最长 60 秒，720p、目标码率 4 Mbps，保存为含音轨的 MP4。开始录像前可修改水印，录制或暂停期间锁定水印和模式。核对后拍摄，照片保留 SDK 返回的 JPEG，视频保留 SDK 返回的 MP4；不重绘、不转码，预览缩略图单独生成。
5. 原片上传到电脑归档，默认显示「已归档 · 未做本地验真」，不自动提交保司官网。断网时已经保存的原片留在手机，联网后自动补传。Android 13 及以上可允许通知权限，查看后台上传通知；拒绝通知不会删除或停止排队资料。
6. 手机记录页可播放、暂停、拖动视频进度并导出 MP4 原片，电脑资料列表也可播放。视频标为「视频已归档 · 未验真」，不计入必需照片数量。
7. 照片本地验真为可选项，默认关闭。只有在电脑配对页明确开启时，新的照片上传才调用官方验真接口，并在明确通过后归档；开关不会补验已归档照片。关闭会暂停此前等待验真的任务。视频暂不支持本地验真，无论该开关状态如何均不调用照片验真接口。

打开相机后未拍摄就退出，不会在照片记录或异常计数中占一条。旧版留下的未拍摄取消、中断记录也不再显示。相机打开前的授权、网络错误仍在相机页面提示；实际返回过照片后发生的保存、上传错误继续显示。已有原片、部分保存文件和上传回执不会因退出相机而删除或隐藏。

拍摄需要 SDK App ID / Secret Key。只有开启本地验真时才需要验真 Group Key / Group Secret。SDK 返回的时间和防伪码仅标作未核验元数据；缺少 SDK 时间时不使用手机时钟冒充水印时间。启用本地验真并通过后，水印时间以官方结果为准。案件归属和水印内容仍需人工核对，拍照和验真不推进案件流程。

## 案件筛选与返回保留（0.5.6）

案件页顶部可同时选择项目和状态：全部状态、查勘、施工、验收；与楼栋、房号、案件号搜索组合筛选。状态使用案件当前工作流阶段，不使用照片的拍摄环节；待结算等其他阶段仍显示在「全部状态」中。

项目、状态和搜索词保存在手机，拍照返回、切换记录页、同步案件、重建页面或重新打开 App 后均沿用上次选择。正式连接按服务器与设备分别保存，示例体验单独保存。同步后没有匹配案件时保留筛选并显示空列表，可切换回「全部项目／全部状态」；长项目名在按钮中省略，在项目选择列表中查看完整名称。

## 上传进度和故障恢复（0.5.5）

在「记录」查看每张照片的传输进度、大小、本次耗时和尝试次数。原片写入网络连接后显示「传输确认中 · 等待服务器回执」，避免把客户端写完误认为服务器已收到。收到匹配的拍摄编号、类型、SHA-256 和归档编号后才显示已归档。状态变化时更新列表，字节进度只更新现有文字和进度条。

每次尝试先查询原拍摄编号的回执；服务器明确返回不存在时才上传原片。响应丢失或超时后再次查回执，已收到的照片不重复发送。回执查询本身失败时等待重试，不把网络错误当作记录不存在。已在工作台删除的记录不重新归档；同一原片的 JPEG/MP4、EXIF、SDK 元数据不修改。

最多两份资料同时传输，其他资料保存在队列；上传使用系统前台任务和持续通知，系统限制前台启动时继续由 WorkManager 调度。网络恢复会唤醒待补传任务，临时网络/服务器故障不再限五次重试；采用 15 秒递增退避，系统可推迟实际运行。取消或断网会断开正在使用的连接，长时间无进展的连接也会释放，防止一直占用上传名额。强制停止应用后需再次打开，由系统恢复任务。

「上传详情 → 复制诊断信息」提供拍摄编号、版本、阶段、大小、耗时、尝试次数、网络类型及错误码，不含设备令牌、签名或照片内容。网络超时、域名解析失败和服务器暂不可用会自动重试；设备失效、权限不足、编号冲突、已删除、超出大小限制、回执不符等显示具体原因，按提示处理后可手动重试。所有失败均保留本机已有文件。

0.5.5 将上传请求与前后回执查询分别记录，显示连接准备、交给网络、等待响应头和读取回执的耗时。配合 IDI 0.2.58 的 `Server-Timing`，可查看服务端接收、解析调度、线程排队、鉴权、归档锁、校验、存储缩略图及归档提交耗时；同一请求的追踪编号可对应服务日志。单调时钟分别测量两端持续时间，不用手机与服务器时钟相减。总耗时已包含分项；接收与解析可能重叠，不能将两端分项再次相加。

统计从上传任务开始，不包含官方 SDK 拍摄、生成原片及其内部联网。等待响应头也可能包含剩余传输和代理等待，不等于 IDI 处理耗时。未收到响应、旧版服务或旧照片没有的分段显示「未记录」，不会回填推测值。本地验真为后续独立流程，不包含在上传接口归档耗时中。代理添加多个 `Server-Timing` 响应头时合并读取，保留 IDI 分段。

本地数据库升级仅新增上传状态和任务归属字段，保留历史记录、配对信息和原片。服务端继续使用现有上传/回执接口，无需为此版本迁移服务端数据库。

## 水印与原生接口

当前账号沿用「IDI 案件现场照片」团队模板，顺序为 **时间 → 官方地点 → 案件号 → 小区 → 位置 → 环节 → 内容**。官方 SDK 生成时间和定位，IDI 自动传入其余五项；案件号采用完整报案编号，位置采用案件的楼栋房号。

接入依据是此次实际提供的 1.3.70 包：

- `CameraViewConfig.kCustomInputItems` 接受 `HashMap<String, String>`，不是 JSON 字符串。
- 通过 `kAppid`、`kNoncestr`、整数 `kTimestamp`、`kSignature` 传入电脑生成的签名；不向手机发送 `kSecretKey`。
- 拍照设置 Photo 模式、单张拍摄、保存确认事件和 CameraX 后端。录像设置 Video 模式、720p、60 秒以及每个拍摄编号独立的 SDK 保存目录；只在切换录像时申请录音权限。
- 在 `kCameraActivityWillDismiss` 事件中读取 `Result.capturedImages`，由 `CapturedImage.getImageData()` 取得原片、`getUserComment()` 取得 SDK 元数据。保存成功后才调用 `dismiss()`。
- 视频在 Activity 返回成功时读取 `CameraActivity.getRecordingResult()`，使用 `RecordingResult.videoInfo.filePath` 保存原文件；校验文件位于本次拍摄目录、MP4 可读取、时长有效，不使用照片回调。SDK `VideoInfo` 不提供照片 UserComment，视频水印时间不伪填为本机时间。
- 只在显式模拟器测试的 debug 包中允许 SDK 的模拟器测试选项；发布包保留官方模拟器拦截。

`EditableCameraActivity` 继承 SDK 相机，只读取官方页面中可见水印的坐标，在其上提供本机无障碍点击入口并打开统一设置面板。更改环节、内容或拍摄模式后，保留同一个拍摄编号，通过已缓存的有效签名和 `kCustomInputItems` 重新打开 SDK 预览；等待旧相机销毁并释放原生资源后才启动新相机，不会修改厂商 HTML、JavaScript 或成片。照片确认页、录像和录像暂停时不提供该编辑入口；一旦已有原片或部分文件，元数据不允许改写。案件号、小区、位置沿用已选案件，时间和官方地点由 SDK 生成。

后端按照片 20 MiB、视频 64 MiB 限制读取，检查视频 MP4 结构、H.264 视频轨、尺寸和时长。60 秒录制停止时容许 SDK 收尾造成的文件时长增加，最多接收 65 秒；不裁剪原片。格式检查不等于内容或真实性验证。视频按拍摄编号与哈希幂等归档，保留删除标记；取消、崩溃恢复不删除任何已有 SDK 文件。视频上传的读超时为 120 秒，失败保留本机原片后重试。

旧版公开文档中的 `Result.images` 不适用于本包。原生 Java 配置没有独立的缩放参数，但随包水印渲染器支持 `watermarkScale`。本版通过自有的本地入口页传入 `0.68`，并把 SDK 的表单 URL 编码规范化，避免空格显示成“+”；随后进入未修改的官方资源页。水印缩放在 SDK 生成原片前完成，不对成片二次处理。团队模板 ID 可留空，但此时需要在官方相机中手工核对模板和字段。时间、地点必须由官方模板保留；是否能通过验真以实际官方验真结果为准。

## 授权与传输

SDK 和验真密钥继续以当前 Windows 用户的 DPAPI 加密保存在档案目录 `secrets/xhey-camera.bin`，不进入 Git、APK 或便携备份。迁机后需重新填写。手机在配对及案件同步时从 `/api/camera/native-authorization` 准备签名并保存到当前连接的私有偏好。厂商签名有效期为 24 小时，APP 最多复用 23 小时，剩余 1 小时时刷新；同一次手机启动内用单调时钟检查有效期，重启后重新同步。案件页回到前台时最多每 5 分钟静默同步一次权限；收到明确的 401/403 时清空当前可拍案件和签名，保留原片、历史令牌及待上传记录。进入拍摄、修改水印、切换模式和连拍复用签名及本地最新案件信息，上传仍实时校验设备、项目、案件号和状态。旧 `/native-session` 接口保留供旧 APP 使用，凭证接口 HTTP 响应禁止代理缓存。旧的密钥下载接口保持停用。

官方 SDK 使用随包提供的原生库和水印资源，并联网取得授权、时间、定位等服务。IDI 收到原片后仅上传到配对的电脑；只有显式开启照片本地验真才额外向 `openapi.xhey.top` 发送照片原片验真。SDK 的内部网络处理以厂商实现为准。原生日志委托不转发签名和配置。拍摄、验真各自受官方试用期及额度限制。

旧 H5 客户端的签名和上传接口仍保留，以兼容已有安装和待上传照片；0.5.1 的正式拍摄入口使用原生 SDK，视频仅允许原生来源。示例体验仍使用 CameraX 自绘照片水印，仅保存在本机，不能当作官方照片。

## 构建

依赖 JDK 21、Android SDK 36、Gradle 9.5.1。将原始 `XheyCameraSDK-v1.3.70.9b61b4a6.Android.zip` 解压到 `android-camera/xhey-sdk/1.3.70/`，保留 ZIP 内的根目录。默认路径为：

```text
android-camera/xhey-sdk/1.3.70/XheyCameraSDK-v1.3.70.9b61b4a6.Android/
  xheycamerasdk-release.aar
  XheyCameraSDKAssets/
```

原始 ZIP SHA256：`7f4c70658063849520684c816c8a643cd0bb0281a0a2eb955f37e4b465afb0a6`。SDK 包和本机配置不进入 Git，构建时必须准备该依赖；可参考 `xhey.properties.example` 覆盖路径，不要混用不同版本的 AAR 与资源。构建只打包 `XheyCameraSDKAssets/`，不会把 AAR 作为普通资产再打包一次。

```powershell
$env:ANDROID_HOME = 'F:\Android\Sdk'
.\android-camera\build.ps1 -Variant debug -Test
.\android-camera\build.ps1 -Variant release -GradlePath 'C:\Gradle\gradle-9.5.1\bin\gradle.bat'
```

发布签名仍读取 `android-camera/signing.properties`，沿用当前 Windows 用户 `.android/idi-camera-signing/` 中的原发布密钥；不进入 Git。0.5.10 的 `versionCode` 为 19。交付副本为 `artifacts/android-camera/IDI-Camera-0.5.10-native.apk`。手机端保留已有照片和上传记录；电脑端 0.2.37 新增人员权限迁移。保留 `not_requested` 与 `verified` 的明确区分。保留 0.4.1 的启动器重复进入保护和拍摄编号关联修复。0.4.2 在冷启动时将无照片、无活动相机的空会话记为取消，并从照片列表和计数中排除；内部会话及任何已有文件不删除，已保存原片继续恢复。
