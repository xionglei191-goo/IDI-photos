# 架构

单机部署：浏览器 → FastAPI API / 静态前端 → SQLite（WAL）与内容寻址档案。

0.2.25 的统一模型状态、规则草稿与受控恢复已实现，操作、故障分类及验收边界见 [业务流程与 AI 故障恢复机制](ai-resilience-workflow.md)。

0.2.26 的 `agent_capabilities.py` 为网页和飞书提供状态回执、官网资料对照、分页、具体待办、反馈预览及明确请求后的维护工具；`019_agent_capabilities.sql` 持久化维护记录并去重。工具清单、指令格式与证据含义见 [Agent 工具说明](agent-capabilities.md)。

## 边界

- `idi/db.py`：连接、事务、显式版本迁移。
- `idi/domain.py`：项目、案件、照片与审计规则。
- `idi/storage.py`：原件不可变保存、缩略图、哈希验证。
- `idi/archive_tree.py`：可直接浏览的项目/案件/阶段目录；独立副本、数据库变更触发、后台同步、冲突保留和恢复重建。
- `idi/imports.py`：文件夹/ZIP/台账导入，保留批次、失败、重复来源。
- `idi/recognition.py`：本地 OCR、可选外部视觉接口、候选字段和保守案件匹配。
- `idi/reports.py`：缺项、模板、报送快照、Excel/Word/ZIP。
- `idi/jobs.py`：持久化任务队列和恢复；任务运行与请求分离。
- `idi/connectors/`：来源适配器。接收流程只读；`feishu_feedback.py` 单独承接明确绑定项目负责人的群内反馈。
- `idi/project_followup.py`：项目阶段汇总、照片与本机资料核验、问题处理及反馈队列；不修改案件办理阶段。
- `frontend/src/`：顶部菜单、左导航、照片表格和工作对话框。

## 数据

项目、案件、维修部位、到访、内容文件、照片、来源记录、导入批次/错误、识别结果、报送模板、报送包/回执、任务、连接配置和审计日志。案件与物理位置分离，业务编号可空。数据目录可通过环境变量指定，默认 `data/`。数据库和原件同时备份。

## 安全与运行

未配置网络时仅监听 `127.0.0.1`。档案目录的 `network.json` 可指定监听地址、本机局域网 IP 和允许的私有 IPv4 网段；未同时配置地址与网段时拒绝开放监听。客户端来源和 Host 分别校验，写操作仍检查同源及自定义请求头，Uvicorn 不采信代理转发头。Windows 防火墙另限定服务端口、专用/域网络、本机地址与允许网段。允许网段内的用户共享同一工作台和官网会话，不提供独立用户权限。系统接口和页面显示实际访问范围与局域网地址。

Cloudflare Tunnel 可通过 `public_origins` 和 `trusted_proxies` 配置：公网来源限定完整 HTTPS 域名，代理限定本机或允许网段内的明确 IP。应用只在 TCP 对端匹配、Host 属于指定公网域名、`X-Forwarded-Proto` 严格等于 `https` 时将请求协议视为 HTTPS，随后执行正常同源校验；客户端地址始终保留 TCP 对端，忽略 `X-Forwarded-For`。其他代理、协议或来源不能借此获得公网入口权限。配置本身不增加用户认证；公网访问是否限制人员由部署者的 Cloudflare Access 策略决定。

禁止把档案目录作为静态目录开放，所有原图按登记的文件 ID 读取。ZIP 不直接解压到任意路径；限制数量/大小并拒绝路径穿越。外部 AI 仅在配置后按手动操作，或单独启用的项目内容审核、飞书群助手调用。密钥支持 Windows DPAPI 加密保存或环境变量，API 只返回是否已配置，档案备份不包含密钥。

## 项目跟进（0.2.18）

只跟进查勘维修案件：官网案件以 `platform_list_entries.scope=repair` 的实际清单归属为准，不能仅凭缓存的办理阶段纳入；未关联官网的本地案件从查勘开始，延续到施工、验收、结算及结束。`decode_case` 返回统一的 `followup_eligible`，项目统计、左侧导航、照片审核、问题清单及反馈发送使用同一范围。没有范围内案件的项目不显示；未关联案件的照片仍在照片归档中处理，不参加项目跟进。退出范围不删除旧检查、绑定或发送历史，也不据此宣称照片问题已解决；旧预览失效、待发送反馈取消。

范围内按现有案件 `workflow_stage` 汇总各项目的阶段数量。阶段代表办理记录，不由照片数量、完工照片或模型答复推进，也不换算工程完成百分比。界面显示检查时间和最近官网同步时间。

资料核验沿用每案 `insurer_template_id` 及进场/共用打卡规则。查勘中只检查查勘要求，施工中增加施工要求，待验收/待结算检查全流程，结束/直接赔付/非维修流程不继续催补。范围仅为本机归档，缺项提示必须写明其他渠道未计入，不能表述为负责人未提交。

本机照片检查包括原件校验、分辨率、亮度、低细节提示、OCR 冲突及未识别字段。短边 720 像素是补原图建议值；亮度和细节指标不等于施工质量结论。可选视觉模型检查内容并保存依据、模型和原件哈希；无模型、失败、截断或无效 JSON 不计为通过。暂停模型后不会把先前的模型问题自动标成已解决。

`010_project_followup.sql` 增加负责人绑定、照片检查记录、问题、检查批次和反馈记录。负责人来自所选群实时成员列表，以 `open_id` 绑定，一个账号可负责多个项目。历史问题在绑定时不自动发送；新问题至少等待 1 分钟归并，单项目自动反馈间隔至少 5 分钟，每条最多 20 项。不根据上传者猜负责人。

反馈先形成持久记录，包含固定问题版本、群、收件人及消息 UUID。发送前重查成员资格、问题状态和资料版本；手动预览携带摘要令牌，内容变化后需重新预览。重复接收和重复点击不重复发同一问题版本。明确失败可重试；超时、中断或缺少远程消息编号为结果不确定，不自动重发，需在群里核对后处理。备份恢复默认暂停检查和自动反馈，取消未发队列，保留不确定发送的核对状态。

0.2.17 起，`followup_feedback_policy.py` 将内部观察与可发送的问题分开。本机资料数量不足始终只作内部归档提示；低像素、亮度、细节和 OCR 失败需核对原图，不能直接形成群内补拍要求。只有案件编号、位置、维修事项齐备，且存在人工确认的具体照片问题/处理动作，或视觉模型提供明确可见依据与具体动作，才进入反馈。模型不确定、泛泛催补或推断阶段的结果仍需人工核对。

`011_feedback_evidence.sql` 保存人工核对记录及其案件/照片依据摘要，并给发送队列增加反馈规则版本和依据摘要。更新照片、案件位置、维修事项或处理要求后，旧确认或旧队列失效。旧版未发出的消息取消，已发送的历史记录保留。官网编号优先作为反馈中的案件编号；同一案件、同一照片的问题合并展示，避免重复发送通用模板。

后台线程仅在正常服务启用工作进程时启动，与收图、OCR 和官网业务写入分开执行。停机后无法实时检查，重启后从持久记录继续。网页查看链接只适用于本机，群反馈不发送无法供其他成员访问的 localhost 链接。

服务器重启时将中断任务恢复为可重试状态；归档写入使用临时文件和原子替换；导出保存固定清单和各原件哈希。日期保持来源语义，未知值留空。

`002_archive_tree.sql` 增加目录同步修订号和托管文件清单。项目、案件、照片、来源和报送记录的写事务同时递增修订号；同步服务读取一致性快照，成功后仅确认该快照的修订号，保留期间新增的变更。目录只从本地照片、报送包与回执文件的父路径生成；仅有项目或案件台账不预建目录，空阶段及空待归档目录也不预建。新增目录文件使用独立临时副本、哈希校验及不覆盖目标的原子发布。重分类先写入并核验新副本，再清理哈希仍一致的旧托管文件；非托管文件、手工改动、链接或路径冲突保留并显式报告。目录清理仅删除已登记且为空的目录，不递归删除用户目录；升级后的首次同步会按此规则清理旧版预建的空目录。

目录树包含当前分类的照片、不可变报送 ZIP 和回执附件；它是可重建视图，不是新的原件来源。已有备份格式不变，恢复后由启动核对补齐目录文件。手工编辑目录副本不会回写原件或数据库。

## 案件智能审阅（0.2.19）

`case_agent.py` 在既有归档与项目跟进服务之上提供案件级工具调用循环。入口位于项目跟进的“案件智能审阅”及案件详情的“智能审阅”。任务按用户操作发起，独立后台线程执行，不占用收图、OCR 或官网同步队列。

模型仅能读取当前案件快照、当前阶段资料要求、明确关联的消息和办理/进场记录，以及清单内经过哈希校验的原图；不能执行 SQL、访问任意路径、发送消息或修改官网。照片、OCR、消息及历史 AI 意见均作为资料而非指令。消息只纳入本案照片来源或绑定项目群中明确包含本案编号的记录，不按发言人、相邻时间或相同房号猜测关联。

当前通过 OpenAI 兼容的 `/chat/completions` 使用原生工具调用，`tool_choice=auto`。原图分批作为后续多模态消息返回；每批最多4张、单次最多24张，图片长边缩至1600像素后送入模型，原件保持不变。单次最多12轮、360秒、接口报告的累计80000 Token；每轮输出上限3500 Token。资料清单最多提供200项，办理/进场/消息分别读取最新60条，超出范围明确列为限制。未查看全部图片时标为部分审阅，不能直接加入反馈。

`012_case_agent.sql` 保存每次请求的资料快照、签名、状态、模型、用量、可观察工具步骤、结构化结果和草稿采纳记录。案件、照片、原件、OCR、模板、关联消息、模型配置或服务审阅策略版本变化后旧结果失效，历史仍可查看。相同未变资料可复用完成记录；重复请求不会创建同案并发任务。停止后丢弃尚未落地的模型结果；重启时中断任务明确标记为未完成，等待重新审阅。备份恢复默认取消待执行审阅。

模型通过 `record_finding` 逐项记录发现，再由 `finish_review` 保存摘要和完整结果，避免部分兼容接口错误序列化嵌套对象数组。每项先校验完整结构及所有证据引用，引用必须属于本案且已实际读取。兼容返回的有效 JSON 字符串列表可无损规范；非法 JSON 不作猜测修复。截断、非法响应、超时或额度用尽不会记为完成；中途记录的发现也不能采纳。可恢复的参数/格式错误保留在过程记录中，随后给出有效结果且证据齐备时可以完成。

审阅输出分为可见问题、待核对事项和内部归档提示。用户选择有直接可见证据的具体问题后可预览并加入项目反馈草稿；此操作不发送消息，也不触发自动群发。发送继续使用既有负责人绑定、证据门槛、预览令牌和幂等队列。发送前重新校验整案快照和原件，防止新增资料已解决问题却仍发送旧建议。普通单图检查不能自动消除案件联合审阅的问题，办理阶段与验收结论也不由 Agent 推进。

## 飞书群助手（0.2.20）

`feishu_agent.py` 将飞书持久收件队列接到多项目 Agent。`013_feishu_agent.sql` 保存各群明确选择的项目范围、设置修订、激活时间、任务、工具步骤、图片分析、官网草稿与消息发件队列。只处理激活后发出且接收完成的新消息；原生 mention 必须指向本应用机器人。新图片等待本地 OCR 完成或明确失败后处理，消息编号去重，重启不把历史收图重新回复。原接收进程只负责持久收件，Agent 的两个处理线程与消息调度独立运行。

`project_agent_tools.py` 提供项目清单/进展、案件搜索、案件资料/记录/要求、原图读取、逐张图片分析归档、本地草稿、官网草稿保存和答复工具。工具参数使用运行内的项目/案件/图片引用，服务端校验群范围、设置修订、原件哈希和照片修订。工具不接受 SQL、路径、地址、权限或业务动作。每次12轮、240秒、70,000累计报告 tokens、最多12张图，每轮最多4个工具。失败、截断及未查看部分保留明确状态。模型前文保留同一会话范围近2小时的最多4条近期记录，较早内容按下述滚动摘要接续；0.2.23起优先按群、回复话题与设置修订划分，没有回复话题时按发言人分别接续。待核对图片可在同话题30分钟内由成员补充编号，无话题时只接续原发言人的图片；已整理图片不会自动带入后续无关查询。

图片分类与案件办理阶段分开；原件不修改，人工确认字段不得覆盖。编号来源冲突或关联不唯一时不自动改案；可见描述保留待人工核对标识。准备草稿只追加本次明确分类的照片，保留用户已有字段与选材；缺失业务时间、人员和维修方式不得猜测。查勘和修复成果之外的环节没有 Agent 官网写入工具。`ReviewBatches.save_for_agent` 固定保存动作，最后 HTTP 边界 `PlatformClient.save_draft_only` 仅接受支持的环节与整数 `state=0`，正式提交入口不进入工具注册表。上传前、每个文件前及最终保存前复查权限和资料版本；保留原件上传回执、保存/回读状态及结果未知，未知写入不自动重试。用户可在案件页核对后使用原有人工提交流程。

日报使用北京时间，仅统计 `followup_eligible` 的查勘维修跟进案件，读取实际台账并由模型概括，数字由程序另行渲染；模型不可写资料、改进度或调用保存工具。按项目与日期唯一入队，负责人来自 `followup_contacts`，只在其绑定群内 @ 本人。当天过期发送窗口记为错过，不补发历日简报。群消息使用持久 UUID，在发送前核对当前绑定、负责人/发言人仍在群内；传输超时、中断或缺少回执记为未知，须人工核对，不能盲目重发。恢复备份默认暂停 Agent、取消尚未发出的消息并保留发送未知状态。

## 网页 AI 对话（0.2.21）

`WorkspaceChat.tsx` 在工作台提供可收起的对话窗和手机布局。`workspace_chat.py` 通过独立白名单复用项目查询、案件记录、原图读取、查勘维修范围汇总和待确认记忆提议；0.2.26 另开放本次用户明确请求的单案刷新和单项照片分析重试。模型不能调用图片整理、官网保存、正式提交或群发送。网页选取的项目范围和案件上下文由服务端验证，每个工具再次核对状态，原图必须通过哈希校验。

`014_workspace_chat.sql` 持久化对话及问题、回答、步骤、来源、模型用量和执行状态。浏览器生成随机对话标识，服务端仅保存其 SHA-256；所有读写和取消接口按该标识隔离对话，标识不出现在 URL 中，也不替代工作台原有网络访问边界。同一浏览器同时只允许一个待处理问题，请求标识防止断线重发重复入队。对话保留最近6个成功问答并使用较早问答的滚动摘要，每个对话最多60轮，最近100个对话可从界面读取。新对话冻结选择的项目清单；更换项目范围会建立新对话。

网页历史恢复使用 `workspaceChatStorage.ts` 保留既有标识，按 localStorage、同站 Cookie、sessionStorage 回退读取，组件重挂载复用同一标识。Cookie 限定当前主机、SameSite=Strict，HTTPS 下增加 Secure；请求仍使用原有标识头，服务端不会按 Cookie 自动放宽所有权检查。选中对话与主动新建状态单独保存，当前标签页的选择优先；没有指针时从同一标识的历史索引恢复。读取失败不会清空选择或伪装成没有记录；只有明确404才尝试其他可访问对话，失效索引中的候选各尝试一次。不同访问地址或浏览器不自动合并，恢复已有入口必须核对原浏览器持有的标识及记录，不能按全库最近记录猜测所有权。

后台线程每轮最多4次工具调用，每问最多12轮、240秒、50000累计报告 Token、12张原图。主动停止后丢弃迟到结果；重启时将执行中问题标为失败，不自动重放；恢复备份取消排队和执行中的对话。模型回复截断、格式无效或超限不显示为成功答案。图片分析后由程序追加实际查看张数和台账阶段，明确图像不能代替完工或验收认定。

## 对话摘要与长期记忆（0.2.22）

`015_agent_memory.sql` 将摘要、记忆和操作修订记录持久化到现有 `archive.sqlite3`，随档案备份恢复。`context_memory.py` 按网页对话标识及飞书会话范围隔离；0.2.23起飞书会话范围按下述显式回复话题优先划分，不合并渠道身份。日报仍查询当前台账，不继承普通群聊摘要。

滚动摘要记录关注事项、对话约定、未决事项和来源问答编号。近期原文预算为估算9000 Token，摘要2600 Token，单批摘要输入22000 Token；使用 UTF-8 字节数估算，不冒充模型实际分词计数。旧问答每批最多12轮，每问最多8次摘要调用、累计90秒；单次40秒并计入原任务的总时长及累计模型用量。每批必须返回完整结构、有效来源且未截断，失败保留旧摘要和游标，不删除原文。历史缺口明确显示数量，大量积压仍保留真正最近的问答。长工具结果保留有效 JSON 与省略标识，不直接截断序列化文本。

`agent_memory.py` 按浏览器偏好、原群发言人偏好、项目和案件隔离长期记忆。模型的 `propose_memory` 必须引用本次用户原话，每次最多4条，只能提出待确认项；工作台人工确认或手工保存后才启用。`read_case` 可由程序保存有限台账字段的快照，不将图像推测、聊天说法或 AI 结论自动确认为事实。记忆保存来源、原话、时间、有效期、修订和资料签名；关联字段变更、群设置变更或到期后暂停引用。台账快照可在重新读取原记录后刷新，人工纠正转换为备注并保留原来源；删除留下无正文的去重标识，防止自动复活。

记忆按当前范围和问题相关性选择，最多20条、估算3200 Token；先使用对应个人偏好与当前案件。每次工具执行和答案落地前复查所引用记忆及摘要修订，用户纠正、删除或来源变更后终止旧上下文答复。所有记忆作为参考资料传入，不能授予权限或代替当前台账；维护动作必须从本次用户原文取得请求，网页仍禁止官网写入和群发送，飞书仍禁止正式提交。

`WorkspaceMemory.tsx` 提供待确认、使用中、待复核状态、来源节选、范围筛选、纠正、删除和 Markdown 导出。网页摘要归属于原浏览器的原对话；飞书摘要可由工作台在包含群全部项目的范围下管理，来源节选仍限定原群、绑定修订与具体回复话题，无话题时限定原成员。清空摘要同时跳过既有历史，避免下一轮又从旧消息生成；原始问答保留。并发编辑用修订号防止覆盖，断线重试创建使用幂等标识。当前工作台依旧按网络访问边界提供项目及群管理能力，尚无独立人员账号或角色体系；个人网页内容不会因项目共享而传给其他浏览器。

## 飞书回复话题协作（0.2.23）

`016_feishu_topics.sql` 增加任务及摘要的话题键、引用别名与话题原文。`feishu_topics.py` 依据事件的 `root_id`、`parent_id`、`thread_id`，以及本机已确认送达的机器人消息回执建立关联。别名按入口、群、绑定修订隔离，后续出现原生话题编号时仍使用原有会话键；引用冲突或格式无效时单独处理，绝不回退到该成员的其他历史。

只补入当前设置生效后已经收录、属于本群的被回复根消息和祖先消息，最多追溯12个节点；不会将发言人此前的整段对话提升为共享话题。未能取得原消息时明确显示上下文不全。没有另行抓取全群历史或声称覆盖停机期间全部话题消息。已收录话题内未 @ 的成员文字可作背景，但不会单独触发答复或视作当前操作请求。

0.2.31 补齐无话题追问的上下文：再次 @ 助手时，另外读取同群、同一发言人在提问前已收录、最近24小时内最后一段未触发答复的普通文字，最多20条，并受独立文本预算限制。该段以最近补充之前最后一次已完成问答的原消息为界，避免把更早不同事项合并成当前请求。消息按发送时间排列，作为 `recent_member_messages` 放在历史问答之后、当前提问之前；不创建问答任务、不主动补发，也不提供业务写入或长期记忆授权。其他成员、其他群、显式回复话题、已归入话题的根消息、旧绑定、已删除消息及提问后才到达的消息均排除。超出条数或预算时明确提示有遗漏；这些补充不自动进入长期摘要。`023_feishu_member_context.sql` 保存清空上下文时的收件边界，保留已有摘要及其历史游标，并兼容升级前已清空的记录。

近期原文和滚动摘要使用同一话题消息流，保留稳定成员标识和来源节选。个人长期偏好仍按入口与发言人识别，不能因为共享话题而继承他人偏好。待核对图片只从对应话题（无话题时对应发言人）近30分钟、当前任务之前的图片任务取得；执行时再次查询，支持成员在图片分析尚未结束时先补充说明，原照片来源、权限和版本检查继续生效。

对话和图片结果使用飞书原消息回复接口，已有话题以话题方式回复；日报沿用绑定群发送。发送前只读核对原消息仍属于当前群且未删除，不能转向其他群或在引用失效时改发全群广播。持续使用原发件队列UUID与结果未知处理。工作台显示共享话题或原发言人范围，共享摘要的纠正、清空影响该话题后续对话，清空不删除原文或重新导入已跳过的祖先记录。

## AI 故障隔离与资料恢复（0.2.25）

018_resilient_workflow.sql 将模型状态、独立规则结果、照片 AI 任务、资料处理依据、人工排除附件和官网保存意图持久化。历史照片只建立不排队的索引；照片或明确编号变更触发定向处理，官网相同值回读不反复触发规则。

ModelRuntime 统一服务识别、跟进检查、案件审阅、群助手、网页问答和摘要调用。按配置版本隔离故障，三次可恢复失败后退避，遵守服务端 Retry-After；最多两个并发，后台照片分析最多一个。恢复先试一项只读照片任务，空队列不探测；配置错误及无效响应不会机械重试。接口响应、有效结构与业务结果分开记录，较早的并发成功不能清除较新的失败暂停。

PhotoAI 单独运行，按资料版本和范围去重，实际发出请求才计次，最多自动尝试三次。领取、请求前及落地时复核原件、照片修订、案件、模型和原群权限；恢复只保存建议，不修改字段或重放 Agent。ProjectFollowup 的规则结果先完成，后续只合并当前有效分析；恢复发现不会自动成为群反馈。

PhotoWorkflow 的本地规则与官网保存使用独立线程。唯一编号或人工确认、明确用途及有效原件才进入本地草稿；prepare_materials 只追加本次资料，保留手工字段和排除项。保存意图限定原群任务、项目和查勘／修复阶段，全部选材必须在本次有效范围；混有其他来源时保留草稿交由人工处理。保存与 Agent 共享材料锁，沿用 ReviewBatches 指纹、上传回执、state=0 和结果未知保护。

Operations 只投影已有记录，提供 GET /api/operations、PUT /api/operations/policy、POST /api/operations/model/retry、POST /api/operations/ai/{id}/retry 和 POST /api/operations/ocr/retry。RuntimeStatus 每十秒在页面可见时读取，显示独立依赖状态与恢复进度；资料读写仍受既有网络请求校验约束。恢复备份暂停新增自动规则及草稿，取消未执行任务并保留未知外部操作。
## 官网系统账号与自动连接（0.2.32）

`PlatformAccount` 将系统账号与登录会话分开管理：账号、密码和自动连接开关一同使用 Windows 当前用户 DPAPI 加密，原子写入 `secrets/platform-account.bin`；数据库仅保存尝试时间、成功时间、失败次数、重试时间和固定错误提示，API 从不回传密码或令牌。档案备份沿用白名单，不包含凭据文件；换机、换 Windows 用户或恢复到新目录后需重新填写账号。

服务后台启动后立即检查连接，之后每5秒检查一次；未配置或关闭开关时不登录。会话过期由既有 HTTP 401 / 业务码2路径清除，后台使用系统账号重新登录。单实例仅允许一次登录，状态接口不被最长100秒的浏览器登录阻塞；服务关闭或会话取消后，迟到的登录令牌不会重新建立连接。网络和限流错误按60秒起、最多30分钟的间隔重试，重试时间跨重启保留；明确拒绝、登录令牌未取得或浏览器环境问题停止自动重试，等待人工修正或点“立即连接”。

`GET/PUT/DELETE /api/platform/account` 查询、保存、移除系统账号，`POST /api/platform/account/connect` 请求一次后台登录。保存后的空密码仅可保留同一个账号的原密码；更换账号必须填写新密码。`DELETE /api/platform/session` 先持久暂停自动连接，再断开；临时登录同样暂停系统账号，防止后续被另一个账号自动接管。连接恢复仅恢复会话，不在登录层重放上传、保存或正式提交。现有业务回执、未知结果回读、人工提交确认和网络访问边界继续生效。
