# 架构

单机部署：浏览器 → FastAPI API / 静态前端 → SQLite（WAL）与内容寻址档案。

## 边界

- `idi/db.py`：连接、事务、显式版本迁移。
- `idi/domain.py`：项目、案件、照片与审计规则。
- `idi/storage.py`：原件不可变保存、缩略图、哈希验证。
- `idi/archive_tree.py`：可直接浏览的项目/案件/阶段目录；独立副本、数据库变更触发、后台同步、冲突保留和恢复重建。
- `idi/imports.py`：文件夹/ZIP/台账导入，保留批次、失败、重复来源。
- `idi/recognition.py`：本地 OCR、可选外部视觉接口、候选字段和保守案件匹配。
- `idi/reports.py`：缺项、模板、报送快照、Excel/Word/ZIP。
- `idi/jobs.py`：持久化任务队列和恢复；任务运行与请求分离。
- `idi/connectors/`：来源适配器。接收流程只读；`feishu_feedback.py` 单独承接明确绑定项目负责人的群内反馈。
- `idi/project_followup.py`：项目阶段汇总、照片与本机资料核验、问题处理及反馈队列；不修改案件办理阶段。
- `frontend/src/`：顶部菜单、左导航、照片表格和工作对话框。

## 数据

项目、案件、维修部位、到访、内容文件、照片、来源记录、导入批次/错误、识别结果、报送模板、报送包/回执、任务、连接配置和审计日志。案件与物理位置分离，业务编号可空。数据目录可通过环境变量指定，默认 `data/`。数据库和原件同时备份。

## 安全与运行

默认仅监听 `127.0.0.1`；写操作检查同源及自定义请求头，保护本地文件导入入口。禁止把档案目录作为静态目录开放，所有原图按登记的文件 ID 读取。ZIP 不直接解压到任意路径；限制数量/大小并拒绝路径穿越。外部 AI 仅在配置后按手动操作或单独启用的项目内容审核调用。密钥支持 Windows DPAPI 加密保存或环境变量，API 只返回是否已配置，档案备份不包含密钥。

## 项目跟进（0.2.18）

只跟进查勘维修案件：官网案件以 `platform_list_entries.scope=repair` 的实际清单归属为准，不能仅凭缓存的办理阶段纳入；未关联官网的本地案件从查勘开始，延续到施工、验收、结算及结束。`decode_case` 返回统一的 `followup_eligible`，项目统计、左侧导航、照片审核、问题清单及反馈发送使用同一范围。没有范围内案件的项目不显示；未关联案件的照片仍在照片归档中处理，不参加项目跟进。退出范围不删除旧检查、绑定或发送历史，也不据此宣称照片问题已解决；旧预览失效、待发送反馈取消。

范围内按现有案件 `workflow_stage` 汇总各项目的阶段数量。阶段代表办理记录，不由照片数量、完工照片或模型答复推进，也不换算工程完成百分比。界面显示检查时间和最近官网同步时间。

资料核验沿用每案 `insurer_template_id` 及进场/共用打卡规则。查勘中只检查查勘要求，施工中增加施工要求，待验收/待结算检查全流程，结束/直接赔付/非维修流程不继续催补。范围仅为本机归档，缺项提示必须写明其他渠道未计入，不能表述为负责人未提交。

本机照片检查包括原件校验、分辨率、亮度、低细节提示、OCR 冲突及未识别字段。短边 720 像素是补原图建议值；亮度和细节指标不等于施工质量结论。可选视觉模型检查内容并保存依据、模型和原件哈希；无模型、失败、截断或无效 JSON 不计为通过。暂停模型后不会把先前的模型问题自动标成已解决。

`010_project_followup.sql` 增加负责人绑定、照片检查记录、问题、检查批次和反馈记录。负责人来自所选群实时成员列表，以 `open_id` 绑定，一个账号可负责多个项目。历史问题在绑定时不自动发送；新问题至少等待 1 分钟归并，单项目自动反馈间隔至少 5 分钟，每条最多 20 项。不根据上传者猜负责人。

反馈先形成持久记录，包含固定问题版本、群、收件人及消息 UUID。发送前重查成员资格、问题状态和资料版本；手动预览携带摘要令牌，内容变化后需重新预览。重复接收和重复点击不重复发同一问题版本。明确失败可重试；超时、中断或缺少远程消息编号为结果不确定，不自动重发，需在群里核对后处理。备份恢复默认暂停检查和自动反馈，取消未发队列，保留不确定发送的核对状态。

0.2.17 起，`followup_feedback_policy.py` 将内部观察与可发送的问题分开。本机资料数量不足始终只作内部归档提示；低像素、亮度、细节和 OCR 失败需核对原图，不能直接形成群内补拍要求。只有案件编号、位置、维修事项齐备，且存在人工确认的具体照片问题/处理动作，或视觉模型提供明确可见依据与具体动作，才进入反馈。模型不确定、泛泛催补或推断阶段的结果仍需人工核对。

`011_feedback_evidence.sql` 保存人工核对记录及其案件/照片依据摘要，并给发送队列增加反馈规则版本和依据摘要。更新照片、案件位置、维修事项或处理要求后，旧确认或旧队列失效。旧版未发出的消息取消，已发送的历史记录保留。官网编号优先作为反馈中的案件编号；同一案件、同一照片的问题合并展示，避免重复发送通用模板。

后台线程仅在正常服务启用工作进程时启动，与收图、OCR 和官网业务写入分开执行。停机后无法实时检查，重启后从持久记录继续。网页查看链接只适用于本机，群反馈不发送无法供其他成员访问的 localhost 链接。

服务器重启时将中断任务恢复为可重试状态；归档写入使用临时文件和原子替换；导出保存固定清单和各原件哈希。日期保持来源语义，未知值留空。

`002_archive_tree.sql` 增加目录同步修订号和托管文件清单。项目、案件、照片、来源和报送记录的写事务同时递增修订号；同步服务读取一致性快照，成功后仅确认该快照的修订号，保留期间新增的变更。新增目录文件使用独立临时副本、哈希校验及不覆盖目标的原子发布。重分类先写入并核验新副本，再清理哈希仍一致的旧托管文件；非托管文件、手工改动、链接或路径冲突保留并显式报告。目录清理仅删除已登记且为空的目录，不递归删除用户目录。

目录树包含当前分类的照片、不可变报送 ZIP 和回执附件；它是可重建视图，不是新的原件来源。已有备份格式不变，恢复后由启动核对补齐目录文件。手工编辑目录副本不会回写原件或数据库。

## 外部接口依据

- FastAPI 官方运行文档：https://fastapi.tiangolo.com/deployment/manually/
- RapidOCR 项目：https://github.com/RapidAI/RapidOCR
- wxauto 监听接口：https://docs.wxauto.org/docs/class/WeChat.html
- wxauto 图片下载：https://docs.wxauto.org/docs/class/Message.html

微信文档描述接口能力，不能据此证明当前客户端兼容；配置后仍需对指定群进行采集、附件下载、去重和重启测试。



## V2 扩展

`004_case_workflow.sql` 增加短编号、独立业务编号、流程状态、五类照片、同步运行记录、办理事件和审核快照。`workflow.py` 负责完整台账回读及双看板；`review_batches.py` 固定选材与字段版本，控制上传提交和回读。`DashboardApp`、`CaseBoard`、`CaseDetail` 替代旧的多菜单首页。官网同步在独立网络线程执行；档案与 OCR 使用本地队列。默认 `IDI_PLATFORM_WRITE=0`，真实官网写入未执行。

`005_platform_lists.sql` 将官网清单归属与案件当前进度分开保存。`platform_list_entries` 按 `(scope, report_receiving_id)` 保存成员、官网顺序、原始列表字段和完整同步批次，一个案件可以同时属于受理和维修清单。仅完整同步可替换已发布清单；部分失败保留旧清单。空清单也有完整发布标记，避免回退到历史案件或本地样例。默认看板按清单成员取数，进度用于筛选，不用于推断官网列表归属。
