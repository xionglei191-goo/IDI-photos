# 飞书核对卡片

资料收集并保存官网草稿后，IDI 可在项目群发送核对卡片：展示案件、环节、业务字段与附件，管理员在飞书中补齐信息、预览并确认正式提交，结果更新回原消息。此入口直接处理人工点击，AI 助手仍无正式提交权限。

当前自动推送覆盖“现场查勘”和“修复成果”。“理赔受理”和“维修成果验收”虽有共用字段与卡片展示能力，尚未接入自动拟提交通知；办理这两个环节仍从工作台进入，不能将表单显示测试等同于已具备自动群推送。

本环节主要资料已齐、仅缺楼栋或入户打卡照片时，也会发送“资料待补齐”卡片并 @ 项目负责人。生成拟提交信息时先回读官网，发送补资料提醒前再核对一次当前案件、当前环节的官网附件；官网已有有效照片即计入完整性，不要求先下载到本地照片库。官网读取失败时等待重试，不依据旧快照发送缺项提醒。查勘打卡不能代替修复阶段打卡，已撤回附件和空占位行不计入。

补资料卡片列出具体缺项并禁用正式提交。仍缺主要成果附件、存在其他错误或有照片待识别核实时，不触发这类提醒。沿用连续 5 分钟无新照片的合并等待；已发出的同案同环节补资料卡片随补齐结果更新，不重复新发。缺项期间每 5 分钟重新核对官网，官网直接补齐也会更新原卡片；正式提交始终要求完整资料和人工确认。

## 接入配置

1. 在飞书开放平台的企业自建应用中开启机器人，并加入接收资料的内部群。沿用现有消息接收长连接；在“事件与回调 → 回调配置”采用长连接接收方式，添加新版“卡片回传交互” `card.action.trigger`。旧版 `card.action.trigger_v1` 不适用。
2. 为应用申请发送消息、更新应用消息卡片、获取群成员、上传图片资源等对应 API 的应用身份权限，并发布使配置生效。常用权限包括 `im:message:send_as_bot`、`im:resource`；群成员和更新消息的权限可按对应 API 页选择。现有收图所需的消息读取权限仍需保留。
3. 在 IDI“资料工具 → 收图入口”启用该飞书群，在“项目跟进”绑定项目的接收群和负责人。负责人用于提醒，不自动获得业务办理权限。
4. 系统管理员进入“系统设置 → 人员与权限”，建立或选择已启用的 IDI 人员，为其分配项目管理员权限；在“飞书人员绑定”选择群、真实群成员和对应 IDI 人员，点击“保存人员绑定”。同一飞书应用内各群共享身份映射，每个 IDI 人员在该应用内只能绑定一个飞书账号。
5. 在“系统设置 → 自动处理”开启“飞书核对提醒”。项目官网写入账号须可用并允许写入，服务及飞书长连接须保持运行。
6. 需要“查看完整资料 / 原件”按钮时，为服务配置手机实际可访问的工作台地址。系统优先使用 `IDI_PUBLIC_ORIGINS`，否则使用已配置的局域网地址；公网地址仍需沿用受信代理和 HTTPS 配置。仅监听本机且没有公网入口时，卡片显示在工作台手动打开拟提交事项的提示。

配置方式参见飞书官方的 [回调概述](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/callback-overview)、[消息 API](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1) 和 [机器人消息及资源权限示例](https://open.feishu.cn/solutions/detail/ticket?lang=zh-CN)。官方文档及后台权限发布成功不等于实际收发验收。

## 日常操作

1. 照片按现有规则归档、分类并逐步保存官网草稿。同一案件连续 300 秒没有新照片后合并拟提交信息；照片未齐继续等待，照片齐全但业务字段待补时仍可收到卡片。
2. 负责人收到卡片后核对项目、位置、案件号、保单、报案编号和当前环节。业务字段与网页核对页共用字段定义，名称、顺序、条件显示和字典名称保持一致；文字说明与人员占整行，其余字段分列显示，窄屏上下排列。自动填写值带“待核对”标识；附件按用途分组，每页最多 6 项，图片可点击放大。照片较多时逐页核对，视频、PDF 和原文件在“查看完整资料 / 原件”中查看。
3. 需要补充时点“补充修改信息”，**原卡片的业务字段区域在原位变为输入框或选择框**，保留当前值、字段顺序、只读信息、案件信息和本页照片。支持文字、日期、字典选项和人员等字段；联系方式等带出项保持只读。点“预览修改后的信息”后原位切回展示，此时尚未保存或正式提交；再次修改保留预览值，点“放弃修改，返回原资料”会丢弃本次未提交修改并恢复原资料。编辑时先预览再翻页，以免丢失未预览的输入。条件字段随已预览的选项变化，需要时再次进入修改；不能在卡片完整编辑的字段在原位置展示完整值并提示转到网页。未匹配当前字典或人员列表的旧值显示“待核对”，不会因打开编辑就被清空。
4. 有权限的人员核对完整信息后点“确认正式提交”，在飞书确认框再次核对案件和环节。修改过字段的预览须由本次修改人本人确认。缺必填项、图片预览失败或内容超出卡片容量时，卡片不会提供可用的直接提交按钮。
5. 卡片依次显示“正在办理”与最终结果。只有官网接受且回读核对一致，才显示“已提交并回读核实”。网页完整资料页仍需使用 IDI 人员账号登录，并按该账号权限办理。

## 结果与异常处理

| 显示或现象 | 处理方式 |
|---|---|
| 提示未绑定人员或没有项目权限 | 系统管理员核对飞书身份绑定与该 IDI 人员的项目角色；群负责人绑定不能替代权限配置。 |
| 字段待补，提交按钮不可用 | 在卡片补齐后先预览；大文本、过多选项及附件原件到完整资料页核对。 |
| 资料已变化或预览已过期 | 使用最新拟提交卡片重新核对。普通预览有效期 7 天，编辑预览 30 分钟；编辑内容不自动保存。 |
| 卡片没有响应 | 核对新版卡片回调订阅、发布状态及 IDI 长连接；仅有消息接收事件不能处理卡片按钮。 |
| 图片预览不可用 | 检查上传图片权限和原件状态，可转到工作台核对；不会因预览失败修改原件。 |
| 提交结果待核实、官网已接收但回读未完成 | 点“回读官网结果”或到工作台查看回执；不要再次提交。 |
| 结果没有及时更新到飞书 | 后台仅重试更新原消息，不重复官网提交；以工作台中的实际提交回执为准。 |
| 发送是否成功不确定 | 先到群内核对，再在 IDI 标记送达情况。若没有取得原消息 ID，卡片按钮会被拒绝，改从完整资料页核对。 |
| 权限撤销、人员停用、离群或入口改变 | 后续操作重新校验并拒绝，尚未执行的确认同样检查；需要重新绑定或恢复合法授权。 |
| 服务在办理中断开 | 已开始的操作不自动重放，先核对回执；从备份恢复时，待办卡片动作全部中断，旧卡片令牌失效。 |

同一张卡片更新后旧按钮令牌失效，回调重发和重复点击不能触发重复提交。官网正式提交前还会重查权限、实际群成员、资料指纹、当前环节和项目写入账号。历史文字提醒保留，不自动重新群发。

## 实现与验证边界

卡片通过飞书 JSON 2.0 发送和更新。SDK 回调只持久入队并返回提示，主服务执行既有核对、提交和回读流程。审计记录包含点击人、绑定版本、核对记录、动作与处理结果。

自动回归使用隔离数据库和模拟飞书、官网客户端，包含实际官方 SDK 事件反序列化与回调分发、网页绑定与完整核对入口。2026-10-28 经用户授权向“照片收集群（内测）”推送了一张模拟卡片，包含 3 张明确标注的示意图，飞书接口接受且群消息回读确认仅有一条；演示操作按钮禁用，没有执行真实案件正式提交。实发时修正了图片参数兼容问题：`fit_horizontal` 不再传入 `size=large`。完整人工回调、线上身份绑定和正式提交流程仍需另行验收。
# 可操作演示

内测体验使用独立的 `demos/feishu-cards.sqlite3`，不创建案件、官网草稿、核对记录或正式办理任务。只有管理员显式创建并绑定原始群消息的演示会话可用；回调复核应用、群、消息、指定飞书成员、人员绑定版本和到期时间。

演示复用正式卡片的展示和输入控件，支持修改、预览、继续修改、放弃修改、模拟确认和重置。按钮明确标注“模拟确认（不提交官网）”，任何演示回调都不进入正式提交队列。演示有有效期，服务重启后保留未到期会话；没有提供 Agent 工具或公开创建接口。
