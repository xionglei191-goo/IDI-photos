# 采集入口与图片识别

## 飞书群收图（0.2.15）

在“资料工具 → 收图入口”选择“接入飞书群”，填写企业自建应用的 App ID / App Secret，验证并选择机器人已加入的企业内部群。启用后，本机后台通过官方 `lark-oapi==1.7.5` 长连接 SDK 接收 `im.message.receive_v1`，无需公网回调地址。后台需要保持运行，电脑关闭期间无法实时接收。

飞书开放平台需启用机器人能力、应用身份的 `im:message.group_msg`（接收群聊所有用户消息）和 `im:message:readonly`（读取消息与下载消息资源），配置长连接事件接收，并发布使权限生效。只配置自定义 webhook 机器人不能读取群消息。当前仅采集选定 `chat_id` 内的用户消息，过滤其他群和机器人消息；应用内没有群消息发送功能。

接收回调只将规范化消息写入 SQLite 持久队列，附件由后台下载归档。支持普通图片、富文本中的多张图片、现有资料库支持格式的文件及视频，沿用单文件 64 MiB 限制。暂不支持的消息类型保留文字说明；不支持的附件格式和下载错误明确列为失败。每个失败消息最多自动尝试 8 次，网页可重新触发下载。

首次启用从当时开始收集，不导入更早历史。此后每 30 秒按固定时间窗口分页补查，只在整段分页成功、消息都持久入队后推进位置，保留 2 秒重叠；服务重新启动后自动接续，停用期间的消息也在重新启用后补查。此机制依赖飞书仍可读取消息及资源，不能恢复已撤回、已删除或平台不再提供的资源；接口失败时保留位置和错误。实时事件时间、补查成功时间、消息队列状态与附件入库数分别显示。

按 `message_id + resource_key` 去重投递，归档原件仍使用 SHA-256 去重；不同消息发送的相同原件保留各自来源。来源包含群 ID、原消息 ID、发送人的 Open ID、原消息时间、本机首次接收时间和附件标识。发送人目前显示稳定 ID，不假定已获取通讯录姓名。相邻文字只取同群同发送人、原消息时间此前 30 分钟的最多 5 条，不把离线补收时挤在一起的接收时间当作原消息时间。

App Secret 使用 Windows DPAPI 以当前用户身份加密，保存在 `data/secrets/`；不进入配置表、审计、浏览器持久存储、日志或进程命令行。普通档案备份不含该目录；恢复备份、更换电脑或 Windows 用户后须重新填写密钥，默认恢复仍禁用入口。下载只访问固定飞书 API 主机，不跟随附件重定向。

官方参考：[接收消息事件](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive?lang=zh-CN)、[获取消息资源](https://open.feishu.cn/document/server-docs/im-v1/message/get-2)、[获取历史消息](https://open.feishu.cn/document/server-docs/im-v1/message/list)、[Python SDK 事件接收](https://open.feishu.cn/document/server-side-sdk/python--sdk/handle-events?lang=zh-CN)。真实接收、下载、重启补收的实测结果另记于 `docs/validation.md`，不能由连接成功状态代替。

## 文件夹收件

在“采集入口”新建入口，选择“文件夹收件”，填写现有目录，可指定项目或固定案件。启用后每 5 秒扫描一次，至少 3 秒未修改的支持文件会被复制归档。

该目录不能是 IDI 数据目录或其父目录。扫描状态、接收消息数、已保存文件数和失败数分别显示。文件路径、大小、修改时间构成收件记录标识，原件 SHA-256 做内容去重；重复启动不会重复建立同一收件记录。

## 标准本地采集接口

新建“标准采集接口”入口并指定收件目录。第三方采集程序先把文件保存到该目录，再调用本机接口。

```http
POST /api/connectors/{connector_id}/events
Content-Type: application/json
X-IDI-Request: 1
```

```json
{
  "source_key": "稳定且可重复投递的消息标识",
  "identity_scope": "外部系统对消息标识范围的说明",
  "group_name": "项目群",
  "sender": "发送人",
  "sent_at": null,
  "message_type": "image",
  "content": "原消息文字",
  "file_path": "D:\\资料收件\\photo.jpg",
  "original_name": "photo.jpg"
}
```

`source_key` 必填，在同一入口内唯一。`message_type` 支持 `text`、`image`、`video`、`file`；没有可靠发送时间时使用 `null`。图片下载失败可传 `error`，消息接收记录仍会保存，但文件状态明确为失败。

接口先记录消息，再尝试保存附件。附件不在配置的收件目录、文件不存在或不可解码，都会留下错误记录。相同来源标识可重复投递；已经成功保存的事件返回重复状态，不会再次入库。失败事件补齐文件后可重新投递。

识别参考同一入口、同群、同发送人在系统接收时间最近 30 分钟内的最多 5 条文字消息。来源中保留引用文字，不将此接收时间当作原消息时间。候选匹配仍需有明确项目、位置和问题内容，或明确报案号。

## 微信适配器

入口代码：`idi/connectors/wxauto.py`。采用 `wxautox4` 的 `WeChat`、`AddListenChat`、`StartListening` 和附件下载接口。只监听配置中的准确群名；不包含发送、转发或回复群消息的功能。

启动前需要管理员准备兼容当前微信版本的授权组件，并完成其本机环境配置。组件安装与授权按 [wxauto 官方说明](https://docs.wxauto.org/) 操作；当前项目没有假定一个已验证的微信版本组合。

采集端把事件先保存为本地 outbox JSON，再投递给 IDI 服务；投递确认后保留为 `.delivered` 文件。UI 消息 ID 只在当前采集会话内去重，不声称具有跨会话全局唯一性；文件内容仍由归档层去重。附件下载失败后，如果没有得到有效文件路径，仅在网页点击重试不能代替重新取得原附件。

当前尚未接通真实微信。接通后需要分别核对：目标群监听、图片/文件原件下载、相邻消息归属、重复消息、断线恢复、微信/系统重启、历史缺口及长时间运行。当前实现不宣称能自动补齐离线期间的所有历史消息。

## 外部图片识别

配置在“系统设置 → 照片识别”。基础地址通常以 `/v1` 结尾，模型需要支持 `image_url` 的聊天消息格式。密钥由运行服务的环境变量提供，可自定义变量名；无需密钥的本地兼容服务也可以使用。

启用外部识别后，仍需选中图片并在“识别”菜单中手动发起。发送前仅为识别生成最长边 1600 像素的 JPEG，归档原件保持不变。自动导入和文件夹收件只触发本地 OCR。

模型返回的 JSON 仅提取允许的字段。原始文字、字段建议和候选案件保留为识别记录；未确定信息保持空白，已人工确认的字段不会被自动覆盖。

官方接口参考：[微信群监听](https://docs.wxauto.org/docs/class/WeChat.html)、[消息和附件下载](https://docs.wxauto.org/docs/class/Message.html)、[RapidOCR](https://github.com/RapidAI/RapidOCR)。文档说明不替代本机实测。
# 项目负责人反馈

在“项目跟进”中，为项目选择已连接的飞书群和群内负责人。机器人收图和负责人身份分开记录，上传者不自动成为负责人。若读取成员失败，检查应用的群成员读取权限及发布状态；发送反馈还需机器人发送消息权限。

项目跟进仅包含查勘维修案件及对应的本机照片；官网案件以查勘维修清单为准，后续验收、结算仍在跟进范围。只有受理、历史待核实等案件的项目不显示，也不生成新反馈。案件退出范围时，待发送反馈会取消，原负责人绑定与历史反馈记录保留。

绑定时可选择自动反馈有明确依据的新问题。已有问题不会自动群发，可在项目页预览后发送。本机未归档、图像指标或 OCR 失败不会直接群发；在“核对问题与动作”中查看原图、记录具体依据和处理要求，或由已配置的视觉模型给出明确可见依据后，才能生成反馈。消息按案件和照片合并，包含官网编号或本机编号、位置、维修事项、台账阶段、文件名、具体问题和处理动作；原群消息时间可用时一并保留。结果显示在“反馈记录”，结果不确定时先核对群消息，避免重复通知。

视觉模型在“系统设置 → 照片识别”中填写接口、模型和密钥，再到“项目跟进 → 检查设置”单独启用内容审核。API 密钥按当前 Windows 用户加密，留空保留，换接口地址需要重新填写；换电脑或恢复档案后需重新配置。未启用模型时，本机规则提供核对线索，具体内容判断由人工核对原图完成；反馈发送本身不依赖模型。模型标注为不确定、只有笼统动作或推断工程阶段的结果不直接群发。
