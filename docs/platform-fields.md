## 编号与关联

三个字段分别保存，不能互换：

| 字段 | 含义 | 本地规则 |
| --- | --- | --- |
| `reportReceivingId` | 官网案件记录 ID | 完整字符串，在线选择案件后核对列表、案件详情及阶段记录关联 |

## 清单归属与流程状态（2026-10-16 更正）

早于 2026-09-24、无受理结果且不在维修清单的记录标为“历史待核实”，仅供查看。此规则依据实际列表缺项和用户反馈，不将“测试阶段”假设写成事实；存在有效受理结果或维修清单成员的早期记录不受该日期规则排除。单案刷新发现现场查勘受理结果时，继续读取维修清单详情，不等受理记录从原清单消失。

修复阶段不自动复用查勘打卡记录。用户确认是同一次进场后，可以在修复栏位明确选用原照片，原归档分类和原文件不变。本地“验收照片 / 完工效果”建议进入修复后照片栏。官网没有独立的施工过程照片栏；是否将过程资料整理为补充 PDF，应按实际案件要求确认。

### 进场记录与共用打卡（0.2.14）

案件详情的“进场与维修记录”按实际每次进场保存日期、标记、起止时间、人数、维修说明和所选原件；同一天再次上门也使用独立记录。未关联进场的照片只按日期暂存分组，不自动判定为同一次施工。

查勘后当天维修且确认为同次进场时，可选用同日的查勘楼栋、入户打卡。原照片仍归查勘，只增加其与这次施工的关联。本地查勘、施工打卡分别计入用途，施工栏显示“共用 N”，原件总数不增加。共用照片不能再次覆盖另一施工进场的打卡；跨案件、跨日期、日期未知、角色未明确或识别冲突的照片不能共用。照片案件、分类或水印时间改变后，原共用关联失效，需重新核对。

施工和本次完工照片可分别关联到各次进场。默认保司过程资料按次检查施工打卡和施工记录；升级只调整未改动的内置要求，自定义要求保留。筛选照片和导出资料保留进场标记及共用关系，每份原件只导出一次；已生成的历史资料包不改写。本地进场记录不自动写入官网，也不改变官网办理进度。

## 文件与时间处理

- 原件不改写。选择和导出均核对案件归属，导出时再次验证 SHA-256；资料包有独立快照与校验值。
- 文件选择器按栏位扩展名过滤；后端再检查扩展名、PDF 文件头和已观察到的大小规则。资料内容和签字真实性仍需人工核对。
- 网页通用附件组件的 20 MiB 限制是严格小于；普通图片/视频组件没有找到明确的网页大小上限。尚未通过真实上传验证服务端限制、最大数量或接收结果。
- 网页对部分大于 1 MiB 的图片有压缩逻辑（目标 500 KB、比例 0.8）。本地上传与导出均使用归档原件，不额外压缩；上传后使用官网返回的文件 ID。
- 官网某些上传回调会用文件 `createDate` 或当天时间填入查勘/开工时间。本地不照搬这一行为；业务时间、水印时间、导入时间分别保留。
- 草稿按案件及环节保存，切换案件、环节或菜单前保存本地修改；关闭网页时如有未保存修改会提示。规则预览不写入官网。
- ZIP 是按栏位整理的本地资料，包含原件、字段清单、待补说明；不会作为整包发送到官网。其副本会进入案件目录的 `报送资料/官网资料准备/`，并包含在系统备份中。

## 连接方式与验证边界

官网登录对账号和密码采用 SM2 加密。本地通过临时 Chrome 页面执行官网正常登录，从登录后的会话读取令牌，再由固定接口白名单执行查询；密码经进程管道传递，不进入命令行、明文文件、数据库或日志。0.2.32 起，“系统账号”可将账号密码按当前 Windows 用户加密保存到 secrets/platform-account.bin，档案备份不包含该文件；开启自动连接后在启动或会话失效时恢复连接。浏览器关闭后仅令牌保留在本地服务内存中，断开或重启即清除。临时登录不保存输入密码，并暂停系统账号自动连接。

查询白名单包括查勘维修列表、理赔受理列表、案件详情、查勘详情、修复详情、维修人员和三类字典查询；启用写入时，另允许文件上传和上述四个业务环节的已核对接口。真实验证已完成正常登录、两类列表及编号搜索、案件回读关联、字典读取和四环节本地预览。连接需要本机 Chrome、Node.js 及项目浏览器依赖。

已定位的文件上传接口为 `POST /insurance/sysFileInfo/upload`，上传字段名为 `file`。文件上传后还需把返回的文件记录关联到正确案件、正确环节。0.2.12 已实现审核快照、上传、官网保存、正式提交及分别回读核对。查勘和修复的保存明确使用 `state=0`，正式提交使用 `state=1`；保存回读必须同时确认字段、附件一致，官网状态为 0 且本地环节未推进。纯参数组装函数不会发送请求。

这些接口来自当前网页，不是已确认稳定的公开开发者 API。当前正式启动器已启用人工核对后的写入。真实验收记录见 `docs/validation.md`，不得以一宗案件的官网保存验证推断所有文件限制或正式业务提交均已验证。
