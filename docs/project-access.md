# 人员、项目权限与官网账号

从 0.2.37 起，网页工作台要求使用 IDI 人员账号登录。系统管理员在「系统设置 → 人员与权限」创建人员、分配项目，并配置各项目官网账号。同一人可以在不同项目担任不同角色。

|角色|可见范围|照片操作|官网正式提交|系统配置|
|---|---|---|---|---|
|系统管理员|所有项目|上传、查看、修改、删除|核对后确认|人员、项目、官网账号和其他配置|
|项目管理员|分配的项目|上传、查看、修改、删除|本项目核对后确认|查看本项目官网账号状态|
|项目成员|分配的项目|APP 或网页上传、查看、下载|不可提交|不可修改|

权限在后端逐次检查，涵盖案件、照片列表与计数、缩略图、原图、资料包、后台任务和操作记录。成员无权通过手工调用 API 修改照片或提交官网。停用人员、移除项目权限会影响后续网页与手机请求；重设密码会注销原登录并撤销手机配对。

## 首次设置

1. 在服务所在电脑打开 `http://127.0.0.1:8766`，创建自己的系统管理员账号；没有默认账号和默认密码。
2. VPS 首次创建管理员需通过 SSH 隧道访问本地端口。公网反向代理入口不能完成首次创建。
3. 登录后添加人员，按项目分配「项目管理员」或「项目成员」。
4. 在「连接与收图」保留公司官网读取账号，在「人员与权限」为每个项目填写对应的官网写入账号。
5. 系统管理员登录后，可在当前公网、局域网或本机入口打开「管理手机连接」，选择人员及其允许访问的项目，生成配对码，无需切换到服务器本机。手机配对后显示绑定人员姓名。未登录用户、项目管理员及项目成员不能管理配对、停用设备或修改官方相机配置。

升级前已有手机设备没有可靠的人员归属，需要重新按人员配对。手机原有照片、待上传原件及服务器历史资料均保留；重新配对后继续上传。历史上传来源不能反推为某个人员，因此显示为历史记录或系统收图。

## 照片与正式提交

现场人员使用 APP 选择案件和照片用途后，原片先上传 IDI，随即进入自动处理和官网草稿保存队列。人工确认不是照片自动保存的前置条件，打卡照片优先处理。文件完整性、案件归属和当前权限仍会自动校验；有实际冲突时显示原因，不能把未成功的保存标为完成。

自动处理只执行官网「保存草稿」，不会推进业务阶段。资料齐全后生成拟提交信息，由 IDI 系统管理员或本项目管理员核对并正式提交。普通网页上传的已有照片依赖识别与分类证据，不能保证缺少案件编号或用途的任意文件直接自动选材。

首次配置项目官网账号会开启照片规则、草稿整理和增量自动保存。之后手工暂停的全局开关会被保留。项目账号的「允许本项目保存和提交」开关可以单独暂停该项目写入；接收和归档照片继续运行。VPS 环境还需启用 `IDI_PLATFORM_WRITE=1` 才允许实际官网写入。

## 公司读取、项目写入

后台任务的「保存进度」按正在处理的项目显示官网账号状态。公司账号已连接时，项目账号仍可能未配置、断线或暂停；系统管理员点击「配置项目账号／查看项目账号」会进入「人员与权限」，自动选中对应项目并定位到官网账号设置。其他人员看到联系管理员的提示。这里只查询状态，打开设置不会保存账号或触发官网业务操作。

- 公司账号只负责公司清单更新、案件读取和照片下载，服务器禁止其上传、修改、撤回或提交。
- 每个项目使用独立的官网会话和加密凭据文件。所有写入、写入前核对及写入后回读都绑定当前项目账号。
- 项目账号断线、密码变更或权限失效时，本项目资料留在 IDI 等待处理，不能改用公司账号写入。
- 更换项目账号会使此前待执行的核对记录失效，需要重新核对。结果不明的远端请求保留为待核实，不能自动重复发送。
- IDI 登录密码以加盐哈希保存；官网密码在 Windows 使用 DPAPI，在 Linux 使用独立主密钥加密。项目成员拿不到官网密码或会话令牌。

「官网操作记录」区分实际上传人员、自动执行或确认人员、项目官网账号、操作和回读结果。自动执行主体显示为系统，同时保留照片的实际来源人员。

## 升级和恢复

升级前备份档案数据库和当前源码。新版本启动时应用迁移 `033_project_access.sql`，保留原项目、案件、照片与设备记录。回退应使用升级前数据库副本及对应旧程序，不让旧程序直接操作已升级的库。

档案备份包含人员及权限数据，但不导出官网密码、平台密钥或其他 `secrets/` 文件。恢复到新服务器后，使用已有 IDI 管理员账号登录，再重新配置公司与项目官网凭据。首次管理员账号请自行妥善保管。
