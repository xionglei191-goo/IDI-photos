# IDI 案件照片资料管理

使用共用前后端源码和 Linux Docker 镜像的工作台，用于整理维修案件照片、核对资料要求、准备官网报送、跟进维修进度并记录反馈。当前版本 **0.2.41**。

当前约定：**本机 Windows 用于开发和隔离测试，246 暂时作为正式服务器**。开发入口为 <http://127.0.0.1:18767>，通过 `start-dev.cmd` 启动；日常业务访问 <https://idi.xionglei.online/>。本机 `18766` 是通往 246 的 SSH 管理入口，不是开发环境。环境、数据及发布流程见 [开发与部署约定](docs/development.md)。

Linux VPS 使用 Docker Compose，包含独立加密主密钥、持久数据卷、CPU OCR、可选 HTTPS 登录入口和备份迁移流程。完整步骤见 [VPS 部署说明](deploy/vps/README.md)。Windows 原生启动方式保留用于兼容和专项调试。

## 功能

- **案件台账**：理赔受理用于总账和发现新案件，查勘维修用于照片管理与报送；同一案件可以同时属于两张清单。每天北京时间 08:00 检查近期受理与未归档维修清单，失败补拉并断点接续；手动同步进行全量对账。
- **统一设置入口**：顶部“系统设置”按连接与收图、自动处理、识别与模型、项目与资料、后台任务、备份恢复六类组织。工作区顶部保留一行运行状态，直观显示存储、OCR、AI、官网、收图和自动保存开关状态；自动保存仅显示“已开启／已暂停”。后台任务的保存进度按“案件号＋已保存内容”紧凑展示，点击案件号进入办理页面。资料工具仅保留全部照片与报送记录，配置开关集中在系统设置。
- **官网同步控制**：每日自动更新在“系统设置 → 自动处理”中开启或暂停，看板仅保留“手动同步”按钮进行完整核对。请求串行限速，按变化读取详情，分批核验官网照片并显示真实核验时间。服务在线且官网登录有效时执行；配置系统账号并开启自动连接后，重启和会话失效可自动恢复。
- **照片归档**：支持文件、文件夹、ZIP、CSV/XLSX 台账导入，以及文件夹和飞书群持续收图；保留原件、哈希、来源、原文件名和各类时间。
- **识别与核对**：本地 OCR 识别案件编号、水印时间、查勘打卡、查勘问题、施工打卡、施工和完工验收用途。无法确定的信息保留待核对状态。
- **后台保存与拟提交**：照片按当前环节静默上传并保存，只有存在资料已齐的待确认案件时才显示“拟提交”区域，由管理人员核对后正式提交。保存进度、缺项和填写依据集中在“系统设置 → 后台任务 → 保存进度”；总开关和历史案件启用集中在“自动处理”。自动填写保留人工修改，未齐资料继续在后台等待。
- **资料准备**：按案件和进场记录检查资料，生成版本化报送包；保存、正式提交和验收结论分别记录，提交前需核对字段及原件。
- **项目跟进**：主界面集中展示项目概览和群助手，跟进查勘维修及后续验收、结算。项目卡片显示办理进度与负责人，可直接查看项目案件。照片检查与群反馈历史放在“记录与工具”，发送异常仍会直接提示；本机归档缺项不作为项目待办展示。
- **案件智能审阅**：在案件详情中按需发起，联合查看原图、维修事项、办理记录和明确关联消息，保存带证据的审阅意见。支持后台进度、历史记录、停止、资料变化失效及反馈草稿。
- **飞书群助手**：群内 @ 机器人查询授权项目和案件，同群同回复话题的多人可共同接续；分析新图片、按明确编号整理，并在查勘或修复成果环节上传和保存官网草稿。每天北京时间 18:00 在负责人绑定群内发送项目简报，Agent 无正式提交权限。
- **网页 AI 气泡**：工作台右下角随时提问，支持项目范围、当前案件上下文、连续追问、已归档照片分析和相关案件跳转；保留本浏览器的对话历史、查询进度和停止状态。
- **AI 记忆管理**：较早问答自动整理成有来源的摘要，近期问答继续保留；按浏览器、群成员、项目和案件保存记忆。点击 AI 助手内的“记忆”，可确认候选、查看来源、纠正、删除及导出，也可管理网页和飞书对话摘要。
- **备份恢复**：备份数据库、原件、缩略图和报送文件并校验内容；恢复到新的空目录，自动接收和反馈默认暂停。

本机没有归档照片不能证明资料未提交；图像指标、OCR 失败及不确定的 AI 结果不会直接生成群内催补。照片数量和完工照片也不会自动推进案件进度。

对话中说“记住这个约定”后，AI 会提出待确认记忆，经工作台核对启用后才长期使用。过期或关联台账变化的记忆暂停引用，台账快照仍以重新查询为准。个人偏好仅用于原浏览器或原群发言人，项目和案件记忆供授权渠道共同参考。工作台沿用现有网络访问边界，群摘要可在包含该群全部项目的查询范围下管理；本版本未增加账号体系。

飞书多人协作时，回复同一条消息、机器人的答复，或在同一原生话题内 @ 机器人，即可接续该话题已收录的讨论与待核对图片。没有回复话题时按发言人分别接续；个人偏好不会转给其他成员。同话题内未 @ 的文字作为背景保留，仍需 @ 才触发文字答复。未收录的原消息、无效或冲突引用会明确提示，不将整个人的其他聊天并入话题。


## 安卓水印相机

安卓相机 0.5.1 使用今日官方 Android 原生 SDK 1.3.70 拍照和录像。预览顶部可切换模式，视频为带声音的 720p MP4、每段最长 60 秒，支持手机播放、导出、断网补传和电脑播放。后端生成拍摄签名，原片原样上传到电脑归档，不自动提交保司。照片本地验真为可选项且默认关闭，启用后新上传照片通过验真再归档；视频暂不支持本地验真，也不计入必需照片数量。模板保留官方时间、地点和五项案件字段；官方 SDK 原片与本地验真结果分别标识。点击拍照直接进入预览并弹出水印设置，取景时点击水印可再次修改环节、部位和内容。未拍摄就退出相机不会显示为拍摄记录；已有原片及保存、上传失败记录仍保留。配置、构建及验收范围见 [android-camera/README.md](android-camera/README.md)。手机配对入口位于“系统设置 → 连接与收图”。

## Windows 原生安装与启动（兼容方式）

日常开发使用 [Docker 开发入口](docs/development.md)。以下方式默认访问原生服务的 `http://127.0.0.1:8766`；在本工作区调试时应明确指定独立测试档案目录，避免启动历史正式档案副本。

准备 Python 3.12（兼容 3.11）、Node.js 24、Chrome 和 Git。在 PowerShell 中执行：

```powershell
git clone https://github.com/xionglei191-goo/IDI-photos.git
cd IDI-photos
.\scripts\setup.ps1 -Python 'C:\Python312\python.exe'
.\scripts\start.ps1
```

如果已安装 Windows Python 启动器 `py.exe`，可以省略 `-Python` 参数。首次安装需要联网，脚本使用 `requirements.lock.txt` 和 `frontend/package-lock.json` 安装依赖、构建前端；本地 OCR 组件随 Python 依赖安装。

安装完成后可双击 `start.cmd` 启动并打开浏览器。保留服务窗口，按 `Ctrl+C` 停止，或双击 `stop.cmd`；停止脚本会核对进程归属。

指定其他端口或档案位置：

```powershell
.\scripts\start.ps1 -Port 8767 -DataDir 'D:\IDI档案'
```

同一档案目录只允许一个受管理的服务实例。首次启动为空档案，需要自行创建项目、导入资料或连接官网同步。

### 局域网访问

未配置时仅供本机访问。要开放局域网，在档案目录（默认 `data/`）创建 `network.json`，填写服务电脑的实际 IPv4 地址及所在网段。以下仅为示例：

```json
{
  "host": "0.0.0.0",
  "lan_hosts": ["192.168.1.10"],
  "lan_subnets": ["192.168.1.0/24"]
}
```

Windows 防火墙需为 TCP 服务端口（默认 8766）添加入站允许规则，限定专用/域网络、该本机地址和指定网段。停止后重新启动服务，启动窗口和“系统设置 → 备份恢复”会显示局域网地址；其他设备使用该地址，不能使用 `127.0.0.1`。网络配置保存在本机档案目录，后续启动会继续生效；地址变更后需同步更新配置和防火墙规则。将 `host` 改回 `127.0.0.1` 并重启可恢复仅本机访问。

允许网段内的用户共享同一工作台与官网会话，当前没有独立用户权限。服务仍检查客户端来源、Host、同源写请求和工作台请求头；直接启动 Python 服务时也执行相同限制。

### Cloudflare Tunnel

Tunnel 运行在另一台局域网设备时，应用路由的 Service 应填写服务电脑的 HTTP 地址，例如 `http://192.168.1.10:8766`，不能填写 Tunnel 设备自己的 `127.0.0.1`。公网域名和浏览器访问使用 HTTPS；HTTP Host Header 保留公网域名，不改成本地 IP。

在现有 `network.json` 中增加明确的公网来源和 Tunnel 设备 IP，例如：

```json
{
  "host": "0.0.0.0",
  "lan_hosts": ["192.168.1.10"],
  "lan_subnets": ["192.168.1.0/24"],
  "public_origins": ["https://idi.example.com"],
  "trusted_proxies": ["192.168.1.20"]
}
```

重启后，只有来自该代理 IP、携带 HTTPS 转发标记且 Host 匹配的请求能使用公网入口；写请求仍须来自同一个 HTTPS 域名。客户端 IP 不从 `X-Forwarded-For` 改写，原局域网访问继续可用。公网入口目前共享工作台的全部权限；若需限制访问人员，在 Cloudflare Access 为域名设置允许策略。

## 官网、飞书与视觉模型

官网通过正常登录页面连接。可在“系统设置 → 连接与收图”保存系统账号并开启自动连接，密码按当前 Windows 用户加密保存，不进入数据库、日志或档案备份；会话令牌仍仅保存在服务内存中。更换电脑或 Windows 用户后需重新设置账号。临时登录不保存输入的密码，并暂停系统账号自动连接。通过启动脚本运行后，可在预提交审核页保存到官网或正式提交；需要只读运行时使用：

```powershell
.\scripts\start.ps1 -ReadOnly
```

直接运行 Python 服务默认关闭官网写入。已关联官网的案件按官网回读的办理状态工作，不能用本地按钮改进度。

飞书在“收图入口”配置企业自建应用与指定群。负责人在“项目跟进”中另行绑定；上传者不会自动成为负责人。应用权限、消息接收方式和外部群设置由使用者在飞书后台配置。微信适配代码保留，兼容性和无人值守接收需在自己的环境验证。

视觉模型可在“系统设置 → 识别与模型”填写兼容接口、模型和 API 密钥，也可使用 `IDI_VISION_API_KEY` 环境变量。网页填写的密钥通过当前 Windows 用户的 DPAPI 加密保存，接口不返回原文。自动照片内容审核需要在“系统设置 → 自动处理 → 调整项目检查”另行开启，未配置时由本地规则提供线索、人工核对原图。

案件级审阅在案件详情的“智能审阅”发起，使用支持多图和原生工具调用的兼容接口。照片会发送到所配置的模型服务；单次最多查看24张图片、执行12轮，未完成的部分会明确标记。审阅后可查看引用原图，选择有具体可见依据的建议，预览并加入项目反馈草稿，再使用现有群反馈流程发送。首次版本按用户操作审阅，不自动扫描全部案件；原件、案件办理阶段和验收结论不由 Agent 改写。

详细流程见 [使用说明](docs/workflow-v2.md)、[接入说明](docs/connectors.md) 和 [官网字段说明](docs/platform-fields.md)。0.2.25 已实现 [业务流程与 AI 故障恢复机制](docs/ai-resilience-workflow.md)：运行栏分别显示收图、本地 OCR、模型及官网状态；规则归案与本地草稿不等待 AI，恢复只补有效照片分析。关闭群内 AI 后仍可规则整理并发送原定统计日报；官网自动保存仍限定本次群任务原有授权，正式提交继续由人工确认。

群助手在“项目跟进 → 群助手”设置，各群可分别选择多个项目、启停对话和图片整理、查看处理记录与草稿。普通文字只在 @ 本应用机器人时响应；新图片按开启后的消息处理，不补处理开启前的历史消息。每次最多分析12张图片、12轮工具调用；超出或未完成的内容明确列为待核对。群内消息和图片会发送给已配置的模型。

图片没有明确案件编号、编号冲突或用途不确定时保留建议；已有人工确认字段不会被覆盖。官网登录失效、必填业务信息缺失或当前环节没有保存动作时保留本机资料。官网草稿保存后回读核对，正式提交始终需要用户在案件页面操作。暂停群助手会停止后续处理与发送；发送结果未知需先核对群内记录，不能自动重发。

日报统计查勘维修跟进范围，按项目负责人已有群绑定发送，每个项目每天最多一份，不猜测负责人，也不会在多个群重复发同一份。未绑定负责人的项目不会发送。本机服务需要在线；允许当日发送时间后1小时内恢复，过期日报不补发。备份恢复后群助手默认暂停。

网页右下角的“AI 助手”使用同一套模型配置。在案件页面新建对话时会带入当前案件，也可选择一个项目或全部项目；切换范围会开启新对话，旧记录可从“最近对话”返回。Enter 发送、Shift+Enter 换行，中文输入法选词时不会误发送。刷新后可继续查看记录，处理中可以停止；连接中断后重发同一请求不会产生重复问题。

对话窗口中的“历史”可查看并接续旧记录。刷新会恢复当前对话及窗口的展开状态；缺少上次对话指针时，会读取本浏览器最近的记录。主动新建的空对话仍保持新建状态，旧记录可随时从历史返回。读取失败会提示重试。对话标识同时保留本地存储、本站 Cookie 和标签页备份；浏览器不允许持久保存时会提示恢复限制。局域网地址与公网域名，以及不同浏览器，初次使用时各自拥有独立标识；切换入口不会自动合并个人记录。

网页助手只查询和分析，不修改照片、上传文件、保存官网草稿或发送群消息。每次最多查看12张已归档原图，实际查看张数与台账阶段另行显示，照片水印和外观不作为验收认定。问题、查询所需的台账和原图会交给已配置模型处理；对话保存在本机数据库中，不同浏览器使用独立对话标识。需要修改或提交时可从答案打开相关案件操作。

## 档案与仓库范围

默认档案位于 `data/`。`data/项目资料/` 是按项目、案件及照片阶段组织的可浏览副本，原件保存在内部归档中。只有本地已有照片或报送文件时才创建对应目录，仅有官网台账的项目、案件及没有资料的阶段不会预建空文件夹。系统会清理已登记且为空的旧目录，保留人工文件及非托管目录。系统生成的目录副本可重建；手工放入该目录的文件不会自动入库，需要通过导入操作登记。

Git 仓库包含源码、数据库迁移、依赖锁文件、启动脚本、通用文档和自动化测试。以下内容保留在本机，不随代码上传：

- 真实案件数据库、照片、报送包、接收目录和备份。
- 账号、密钥、环境文件、会话和运行日志。
- 本地验收截图、逐案验证记录、一次性验收脚本及私人样例材料。
- 虚拟环境、前端依赖和构建产物。

私人样例导入工具不属于仓库安装流程；直接从页面导入自己的资料即可。业务数据迁移使用备份工具，不使用 Git 同步运行目录。

## 备份与恢复

可在网页“系统设置 → 备份恢复”创建备份，也可执行：

```powershell
.\scripts\backup.ps1
```

恢复到新的空目录：

```powershell
.\scripts\stop.ps1
.\scripts\restore.ps1 -Archive 'D:\备份\idi-backup-实际标识.zip' -Target 'D:\IDI恢复档案'
.\scripts\start.ps1 -DataDir 'D:\IDI恢复档案'
```

备份包含一致性数据库快照及已归档文件，不包含密钥、外部收件目录、未归档暂存文件或未导入的手工资料。恢复会验证文件、数据库完整性和外键关系，重新配置并确认接收入口后再恢复运行。
