# IDI 案件照片资料管理

Windows 本地工作台，用于整理维修案件照片、核对资料要求、准备官网报送、跟进维修进度并记录反馈。当前版本 **0.2.18**，默认地址为 <http://127.0.0.1:8766>，默认仅供本机访问。

## 功能

- **案件台账**：理赔受理、查勘维修分别按官网清单展示，共用项目、楼栋和案件导航；同一案件可以同时属于两张清单。
- **照片归档**：支持文件、文件夹、ZIP、CSV/XLSX 台账导入，以及文件夹和飞书群持续收图；保留原件、哈希、来源、原文件名和各类时间。
- **识别与核对**：本地 OCR 识别案件编号、水印时间、查勘打卡、查勘问题、施工打卡、施工和完工验收用途。无法确定的信息保留待核对状态。
- **资料准备**：按案件和进场记录检查资料，生成版本化报送包；保存、正式提交和验收结论分别记录，提交前需核对字段及原件。
- **项目跟进**：只跟进查勘维修案件，包含后续验收和结算。负责人按飞书群成员账号绑定，有明确照片依据和处理动作的问题才能反馈。
- **备份恢复**：备份数据库、原件、缩略图和报送文件并校验内容；恢复到新的空目录，自动接收和反馈默认暂停。

本机没有归档照片不能证明资料未提交；图像指标、OCR 失败及不确定的 AI 结果不会直接生成群内催补。照片数量和完工照片也不会自动推进案件进度。

## 安装与启动

准备 Python 3.12（兼容 3.11）、Node.js 24、Chrome 和 Git。在 PowerShell 中执行：

```powershell
git clone https://github.com/xionglei191-goo/IDI-photos.git
cd IDI-photos
.\scripts\setup.ps1 -Python 'C:\Python312\python.exe'
.\scripts\start.ps1
```

如果已安装 Windows Python 启动器 `py.exe`，可以省略 `-Python` 参数。首次安装需要联网，脚本使用 `requirements.lock.txt` 和 `frontend/package-lock.json` 安装依赖、构建前端；本地 OCR 组件随 Python 依赖安装。

安装完成后可双击 `start.cmd` 启动并打开浏览器。保留服务窗口，按 `Ctrl+C` 停止，或双击 `stop.cmd`；停止脚本会核对进程归属。

指定其他端口或档案位置：

```powershell
.\scripts\start.ps1 -Port 8767 -DataDir 'D:\IDI档案'
```

同一档案目录只允许一个受管理的服务实例。首次启动为空档案，需要自行创建项目、导入资料或连接官网同步。

## 官网、飞书与视觉模型

官网在页面中正常登录，密码和会话令牌只在内存中保留。通过启动脚本运行后，可在预提交审核页保存到官网或正式提交；需要只读运行时使用：

```powershell
.\scripts\start.ps1 -ReadOnly
```

直接运行 Python 服务默认关闭官网写入。已关联官网的案件按官网回读的办理状态工作，不能用本地按钮改进度。

飞书在“收图入口”配置企业自建应用与指定群。负责人在“项目跟进”中另行绑定；上传者不会自动成为负责人。应用权限、消息接收方式和外部群设置由使用者在飞书后台配置。微信适配代码保留，兼容性和无人值守接收需在自己的环境验证。

视觉模型可在“系统设置 → 照片识别”填写兼容接口、模型和 API 密钥，也可使用 `IDI_VISION_API_KEY` 环境变量。网页填写的密钥通过当前 Windows 用户的 DPAPI 加密保存，接口不返回原文。自动照片内容审核需要在“项目跟进 → 检查设置”另行开启，未配置时由本地规则提供线索、人工核对原图。

详细流程见 [使用说明](docs/workflow-v2.md)、[接入说明](docs/connectors.md) 和 [官网字段说明](docs/platform-fields.md)。

## 档案与仓库范围

默认档案位于 `data/`。`data/项目资料/` 是按项目、案件及照片阶段组织的可浏览副本，原件保存在内部归档中。系统生成的目录副本可重建；手工放入该目录的文件不会自动入库，需要通过导入操作登记。

Git 仓库包含源码、数据库迁移、依赖锁文件、启动脚本、通用文档和自动化测试。以下内容保留在本机，不随代码上传：

- 真实案件数据库、照片、报送包、接收目录和备份。
- 账号、密钥、环境文件、会话和运行日志。
- 本地验收截图、逐案验证记录、一次性验收脚本及私人样例材料。
- 虚拟环境、前端依赖和构建产物。

私人样例导入工具不属于仓库安装流程；直接从页面导入自己的资料即可。业务数据迁移使用备份工具，不使用 Git 同步运行目录。

## 备份与恢复

可在网页“系统设置 → 备份与运行”创建备份，也可执行：

```powershell
.\scripts\backup.ps1
```

恢复到新的空目录：

```powershell
.\scripts\stop.ps1
.\scripts\restore.ps1 -Archive 'D:\备份\idi-backup-实际标识.zip' -Target 'D:\IDI恢复档案'
.\scripts\start.ps1 -DataDir 'D:\IDI恢复档案'
```

备份包含一致性数据库快照及已归档文件，不包含密钥、外部收件目录、未归档暂存文件或未导入的手工资料。恢复会验证文件、数据库完整性和外键关系，重新配置并确认接收入口后再恢复运行。

## 开发与测试

后端位于 `idi/`，前端位于 `frontend/src/`，数据库迁移位于 `idi/migrations/`，后端测试位于 `tests/`。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests/test_project_followup.py tests/test_workflow_source.py tests/test_workflow_v2.py -q
cd frontend
npm.cmd run build -- --outDir dist-test
npm.cmd run test:e2e
```

浏览器测试使用 `dist-test`、独立临时数据库和 8770 端口，不修改日常档案或正式前端。构建正式前端时运行不带 `--outDir` 的 `npm.cmd run build`；开发模式通过 Vite 转发 `/api` 到本机后端。

0.2.18 的项目跟进与流程专项共 106 项相关测试已通过，另有正式页面和隔离页面验证；这不代表已运行全量测试。单元测试中的账号、令牌和案件编号均为测试用值，真实环境需要使用自己的账号和资料。

业务范围见 [需求](docs/requirements.md)，模块划分与数据边界见 [架构](docs/architecture.md)。
